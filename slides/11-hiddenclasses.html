hidden classes

V8 opisuje kształt obiektu ukrytą klasą (Map): jakie pola, pod jakim offsetem. Obiekty o tym samym kształcie współdzielą ją, a inline cache zamienia obj.x w odczyt spod stałego offsetu — jak struct w C. Im więcej kształtów widzi jedno miejsce w kodzie, tym wolniej.
monomorphic — 1 kształt
Stały offset, zero lookupów. Cel każdego hot patha.
polymorphic — 2–4 kształty
IC porównuje kształt z krótką listą. Wolniej, ale JIT nadal działa.
megamorphic — >4 kształtów
IC się poddaje → generyczny lookup, koniec inliningu (ale to nie deopt).
✗ niszczy kształt
const a = { x: 1, y: 2 };  // HC1
const b = { y: 2, x: 1 };  // HC2 — inna kolejność!
p.z = 3;                   // pole po konstrukcji → nowa HC
delete p.x;                // → dictionary mode
✓ zachowuje kształt
function Point(x, y) {
  this.x = x; this.y = y;
  this.z = 0;       // wszystkie pola w konstruktorze,
}                   // zawsze ta sama kolejność
obj.cache = null;   // null zamiast delete
benchmark — suma .x + .y po 500 000 obiektów
1 vs 4 vs 32 hidden classes — ten sam kod odczytu.
wariant avg (ms) min max względnie

Każdy wariant ma osobną funkcję sumującą (własny inline cache) — jedna wspólna mieszałaby kształty i nie pokazałaby efektu mono/poly/megamorphic.
