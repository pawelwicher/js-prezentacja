Optymalizacja JS — silnik V8

RegExp — silnik Irregexp i catastrophic backtracking

Jak V8 wykonuje wyrażenia regularne
V8 używa silnika Irregexp — opartego na backtrackingu; wzorzec jest kompilowany do bytecode'u, a gorące do kodu natywnego
Literał /.../ jest kompilowany raz; new RegExp(str) w pętli rekompiluje za każdym razem — wynieś go poza hot path
Do wyszukiwania literału użyj includes / indexOf / split — bywają szybsze i nie grożą backtrackingiem
V8 ma eksperymentalny liniowy silnik (flaga l) odporny na ReDoS dla wspieranego podzbioru składni
Catastrophic backtracking (ReDoS)
Zagnieżdżone / nakładające się kwantyfikatory — (a+)+$, (a|a)*, (.*)* — dają wykładniczą liczbę kombinacji do sprawdzenia
Na danych prawie pasujących silnik próbuje wszystkich podziałów zanim się podda → zawieszenie wątku
To luka bezpieczeństwa — atakujący jednym krótkim ciągiem blokuje serwer (Denial of Service)
Mitygacje: nie zagnieżdżaj kwantyfikatorów, kotwicz wzorzec, używaj [^"]* zamiast .*, ograniczaj długość wejścia
✗  Podatny wzorzec — wykładniczy backtracking
// Zagnieżdżony kwantyfikator (a+)+ nad tym samym znakiem
const vuln = /^(a+)+$/;

// Wejście prawie pasujące: same 'a' + 1 znak psujący
const input = 'a'.repeat(n) + '!';

vuln.test(input); // czas rośnie ~2^n !
✓  Bezpieczny wzorzec — liniowy
// Bez zagnieżdżenia — jeden kwantyfikator
const safe = /^a+$/;

// To samo wejście, dowolnie długie
const input = 'a'.repeat(100000) + '!';

safe.test(input); // natychmiast, O(n)
DEMO — czas dopasowania /^(a+)+$/ rośnie wykładniczo z długością wejścia
Pomiar przerywa się automatycznie po przekroczeniu ~150 ms — strona się nie zawiesi.
Długość wejścia (liczba „a") Podatny (a+)+ Bezpieczny a+

🛡️ Traktuj każdy regex na danych użytkownika jak powierzchnię ataku. Jeden podatny wzorzec w walidacji e-maila czy URL-a potrafi zablokować cały proces Node.js. Audytuj wzorce (np. narzędziem safe-regex), ograniczaj długość wejścia i preferuj proste, kotwiczone wyrażenia bez zagnieżdżonych kwantyfikatorów.
