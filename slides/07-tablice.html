tablice — elements kinds

V8 śledzi, co tablica trzyma w środku i dobiera reprezentację: od upakowanych intów po hash mapę. Przejścia są jednokierunkowe — jeden zły push degraduje tablicę na zawsze.
PACKED_SMI ──float──→ PACKED_DOUBLE ──obiekt/string──→ PACKED_ELEMENTS │ dziura │ dziura │ dziura ▼ ▼ ▼ HOLEY_SMI ──────────→ HOLEY_DOUBLE ──────────────────→ HOLEY_ELEMENTS ← nigdy w lewo, nigdy w górę · dziura = delete, new Array(N), zapis poza length bardzo rzadka tablica (zapis >1024 ponad length) → DICTIONARY — hash mapa zamiast bufora
packed — zwarty bufor
Każdy indeks ma wartość → odczyt bez sprawdzania, JIT generuje kod jak dla tablicy w C
SMI: inty bez boxingu · DOUBLE: unboxed 8 B/element · ELEMENTS: wskaźniki
holey — tablica z dziurami
Każdy odczyt: czy to dziura? — a dziura może mieć wartość z Array.prototype, więc trzeba sprawdzać prototypy
Dziurę robi new Array(N), delete arr[i], [1, , 3], zapis poza length
elements-kinds.js — node --allow-natives-syntax
const a = [1, 2, 3];   // PACKED_SMI_ELEMENTS — najszybszy layout
a.push(3.14);          // → PACKED_DOUBLE_ELEMENTS   (nieodwracalne)
a.push("hello");       // → PACKED_ELEMENTS          (nieodwracalne)
a.pop();               // dalej PACKED_ELEMENTS — usunięcie nie cofa degradacji
delete a[0];           // → HOLEY_ELEMENTS — najwolniejszy wariant liniowy

%DebugPrint(a);        // ← podgląd aktualnego elements kind
Reguły: nie używaj new Array(N) (→ Array.from) ani delete arr[i] (→ splice); trzymaj jednorodne typy. Pomiar wpływu na odczyt — slajd 10.
