Koniec vs początek tablicy — push/pop O(1), shift/unshift O(n)

Operacje na końcu — tanie
push / pop działają na ostatnim indeksie — nie ruszają pozostałych elementów
Koszt O(1) amortyzowany (czasem realokacja bufora przy rozrastaniu, ale rzadko)
Indeksy elementów się nie zmieniają — żadnego przepisywania
Operacje na początku — drogie
shift / unshift wstawiają/usuwają z przodu → wszystkie pozostałe elementy trzeba przenumerować (memmove)
Pojedyncza operacja to O(n); użycie tablicy jako kolejki przez shift() daje pętlę O(n²)
splice w środku też przesuwa „ogon" — również O(n)
Lekarstwo: wskaźnik na głowę zamiast shift, bufor cykliczny, albo push + jednorazowy reverse
✗  Kolejka przez shift() — O(n²)
const q = buildQueue(N); // [0,1,2,...,N-1]
let sum = 0;
while (q.length) {
  // każdy shift przesuwa cały „ogon" tablicy
  sum += q.shift();
}
✓  Wskaźnik na głowę — O(n)
const q = buildQueue(N);
let sum = 0, head = 0;
while (head < q.length) {
  // nic nie przesuwamy — tylko przesuwamy indeks
  sum += q[head++];
}
// (opcjonalnie q.length = 0 na końcu)
