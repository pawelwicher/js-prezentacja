Optymalizacja JS — silnik V8

Inlining w TurboFan — abstrakcja bywa darmowa

Co to jest inlining
TurboFan wkleja ciało wywoływanej funkcji w miejsce wywołania — znika narzut call/return i przekazywania argumentów
Ważniejsze: optymalizacje działają teraz ponad granicą funkcji — constant folding, eliminacja martwego kodu
Escape analysis — jeśli wklejony obiekt nie „ucieka", V8 może w ogóle nie alokować go na stercie (scalar replacement)
Co sprzyja wklejeniu
Małe ciało — V8 ma budżet inliningu liczony w bytecodzie; krótkie funkcje wchodzą najłatwiej
Gorące i monomorficzne call-site — wiadomo dokładnie którą funkcję wkleić
Funkcje czyste, bez efektów ubocznych — łatwiejsze do dalszej analizy
Co blokuje inlining
Duże funkcje — przekraczają budżet; rozbij hot path na mniejsze kawałki
Polimorficzny / megamorficzny call-site — V8 nie wie którą wersję wkleić
eval, with, dostęp do arguments w starszych wzorcach — psują analizę
✓  Mały helper — i tak zostanie wklejony
function square(x) { return x * x; }

function sumWithCall(n) {
  let s = 0;
  for (let i = 0; i < n; i++) s += square(i);
  return s;
}
// monomorficzny call-site + krótkie ciało
// → TurboFan wkleja square() w pętlę
=  Ręcznie „rozwinięte"
function sumInlined(n) {
  let s = 0;
  for (let i = 0; i < n; i++) s += i * i;
  return s;
}
// dokładnie to samo, co wygeneruje JIT
// po wklejeniu square() — wydajność ~identyczna
