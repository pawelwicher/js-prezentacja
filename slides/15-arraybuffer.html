TypedArray

ArrayBuffer to surowy blok bajtów — zero tagowania, zero nagłówków per element, jeden węzeł dla GC. Dla dużych jednorodnych danych liczbowych to 4–32× mniej pamięci niż zwykły Array.
zużycie pamięci — 1 000 000 elementów
typ B / element 1 mln vs Array zastosowanie
Array OBJECT_ELEMENTS ~32~32 MB mieszane typy, po push(null)
Array DOUBLE_ELEMENTS 8~8 MB 4× jednorodne liczby, brak dziur
Float64Array 88 MB 4× fizyka, finanse, ML
Float32Array / Int32Array 44 MB 8× WebGL, audio, indeksy
Uint16Array 22 MB 16× mesh 3D, audio 16-bit
Uint8Array 11 MB 32× RGBA, dane binarne, WASM
✗ Array.slice() — zawsze kopiuje
const big = new Array(1_000_000).fill(1.0);
const chunk = big.slice(0, 10_000);
// O(n) czas i O(n) pamięć — pełna kopia
✓ TypedArray.subarray() — widok
const big = new Float64Array(1_000_000).fill(1.0);
const chunk = big.subarray(0, 10_000);
// O(1), zero kopiowania — ten sam ArrayBuffer
Pułapka zwykłych Array: jedno push(null) / arr[i] = undefined na tablicy liczb przepisuje ją na OBJECT_ELEMENTS — pamięć rośnie ~4×, a liczby spoza SMI lądują w pudełkach na stercie.
