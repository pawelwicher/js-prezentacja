profiling

Workflow: nagraj → znajdź long task → rozwiń flame chart → popraw → zmierz ponownie. Szukaj szerokich bloków z dużym self time — to one są wąskim gardłem, nie ich rodzice.
DevTools → Performance 1. nagraj 10–30 s realnego użycia (nie zimny start — JIT potrzebuje rozgrzewki) 2. znajdź long taski (>50 ms) w wątku Main — czerwone oznaczenia 3. rozwiń flame chart: szerokość = czas, w dół = zagnieżdżone wywołania 4. optymalizuj funkcje z dużym self time (czas bez callees) 5. wynik potwierdź pomiarem — performance.mark / measure, nie wrażeniem kategorie: Scripting (JS + JIT + GC) · Rendering (style/layout) · Painting · Idle częste piki GC = za dużo alokacji · schodkowy wykres pamięci = wyciek
✓ performance.mark / measure
performance.mark('start-parse');
const result = parseData(raw);
performance.mark('end-parse');
performance.measure('parse', 'start-parse', 'end-parse');
// widoczne w Performance → Timings,
// rozdzielczość do 5 µs (Date.now: 1 ms)
✓ PerformanceObserver — long taski w prod
new PerformanceObserver(list => {
  for (const e of list.getEntries())
    report('Long Task', e.duration);  // → monitoring
}).observe({ type: 'longtask', buffered: true });
