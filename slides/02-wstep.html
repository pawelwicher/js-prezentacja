optymalizacja-js

wstęp

Najpierw zmierz, potem optymalizuj. Największe zyski daje algorytm i struktura danych — mikro-optymalizacje pod JIT mają sens tylko w zmierzonych hot pathach.
co daje najwięcej
Złożoność — Map/Set O(1) zamiast includes/indexOf O(n); zagnieżdżone pętle zabijają duże dane
DOM — batchuj zmiany; nie mieszaj odczytów geometrii (offsetHeight) z zapisami → wymuszony reflow
Asynchroniczność — Promise.all zamiast sekwencyjnego await; ciężkie obliczenia do Web Workera
Kształt obiektów — V8 lubi stałe kształty; dynamiczne dodawanie/usuwanie pól w hot path = deoptymalizacja
gdzie ucieka pamięć
Niewyrejestrowane — listenery, setInterval, subskrypcje żyjące po usunięciu komponentu
Cache bez limitu — rosnący w nieskończoność Map; użyj LRU lub WeakMap
Detached DOM — element usunięty z drzewa, ale trzymany przez zmienną JS
Niemutowalność — {...obj} wszędzie generuje śmieci; w hot path czasem lepiej mutować
"Premature optimization is the root of all evil." — Donald Knuth, 1974 pełny cytat: zapomnij o małych optymalizacjach w ~97% przypadków, ale nie przegap krytycznych 3% — i właśnie o te 3% jest ta prezentacja.
Profiler nie kłamie, intuicja często tak. DevTools → Performance / Memory pokazują, gdzie naprawdę jest problem.
