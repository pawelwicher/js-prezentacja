Dla programisty jest jeden typ number (64-bit double, IEEE 754). Dla V8 są dwa światy: Smi — mały int upakowany w słowie wskaźnika, zero alokacji — i HeapNumber — pudełko na stercie dla całej reszty.
Smi (small integer) HeapNumber [ wartość int · 31/32 bity | tag 0 ] [ wskaźnik na stertę | tag 1 ] zero alokacji, arytmetyka CPU │ zakres ±2³⁰ (kompresja wskaźników) └─→ [ 64-bit double IEEE 754 ] floaty, NaN, Infinity, duże inty
IEEE 754 — pułapki, które musisz znać
Bezpieczne inty tylko do 2⁵³−1 — wyżej „dziury": 2**53 === 2**53+1 → true
Zaokrąglenia — 0.1 + 0.2 !== 0.3; porównuj z tolerancją Number.EPSILON
NaN — jedyna wartość, dla której x !== x; sprawdzaj Number.isNaN
co z tego wynika dla wydajności
Pętle po małych intach (indeksy, liczniki) są najszybsze — wszystko zostaje w Smi
Jeden push(0.5) do tablicy intów przepisuje ją na double — nieodwracalnie (→ slajd 07)
Pola double w obiektach to wskaźnik na HeapNumber (V8 usunął unboxing pól w 2020)
ieee754.js
console.log(2 ** 53 === 2 ** 53 + 1);   // true  — dziura poza safe range
console.log(0.1 + 0.2 === 0.3);          // false — 0.30000000000000004
console.log(NaN === NaN);                // false — używaj Number.isNaN()
console.log(Object.is(+0, -0));          // false — choć +0 === -0 daje true
