Optymalizacja JS — silnik V8

Stringi w V8 — nie zawsze ciągły bufor znaków

Reprezentacje stringa
SeqString — rzeczywiste znaki w ciągłym buforze; Latin1 (1 B/znak) lub UTF-16 (2 B/znak)
ConsString — wynik konkatenacji: trzyma tylko wskaźniki na lewy i prawy fragment. a + b to O(1), bez kopiowania znaków
SlicedString — podciąg jako widok (offset + length) na oryginał; substring nie kopiuje
ThinString — powstaje po internalizacji; przekierowuje na wersję internowaną
ExternalString — znaki trzymane poza stertą V8 (np. źródło z C++)
Flattening i internalizacja
Flattening — operacje wymagające ciągłych znaków (RegExp, kodowanie, część porównań) wymuszają zmaterializowanie ConsString → kopia O(n)
Zbuduj string raz, potem czytaj — wielokrotne spłaszczanie tego samego drzewa to zmarnowana praca
Internalizacja — klucze obiektów i identyfikatory są deduplikowane; porównanie === sprowadza się do porównania wskaźnika
Latin1 → UTF-16: jeden znak spoza Latin1 (np. emoji, część znaków CJK) podwaja rozmiar całego stringa
BENCHMARK — budowanie długiego stringa: += vs array.join('')
A  Konkatenacja +=
let s = '';
for (let i = 0; i < N; i++) {
  s += 'fragment_' + i + ';';
}
// w nowoczesnym V8 każde += to tani ConsString
return s.length;
B  push + join
const parts = [];
for (let i = 0; i < N; i++) {
  parts.push('fragment_' + i + ';');
}
return parts.join('').length;
200 000 fragmentów, 30 powtórzeń — średnia.

🧵 Mit „+= jest wolne" jest nieaktualny. Dzięki ConsString konkatenacja jest tania, a join bywa wolniejszy ze względu na tablicę pośrednią. Realny koszt pojawia się dopiero przy wielokrotnym spłaszczaniu tego samego długiego stringa — np. czytaniu go w pętli operacją wymagającą ciągłych znaków.
