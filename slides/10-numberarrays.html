elements kinds w praktyce

Ta sama pętla odczytu, 7 wariantów tej samej tablicy liczb — od PACKED_SMI po DICTIONARY. Różnica bierze się wyłącznie z wewnętrznej reprezentacji.
fabryki — jak tworzymy warianty
// PACKED_SMI — push samych intów
const a = []; for (let i = 0; i < N; i++) a.push(i);

// HOLEY_SMI — dziury co 10 elementów
const a = []; for (let i = 0; i < N; i++)
  if (i % 10 !== 0) a[i] = i;

// DICTIONARY — skok indeksu >1024 ponad length
const a = [];
a[2_000_000] = 1; // wymusza tryb słownikowy
for (let i = 0; i < N; i++) a[i * 10] = i;
pomiar — hot path odczytu
// Identyczna KOPIA tej funkcji dla każdego wariantu —
// osobna deklaracja = osobny inline cache (wspólna
// widziałaby 7 elements kinds → generyczny IC)
function benchRead(array) {
  let sum = 0;
  for (let i = 0; i < array.length; i++) {
    const v = array[i];
    if (v !== undefined && v !== null)
      sum += typeof v === 'object' ? v.v : v;
  }
  return sum;
}
N = 100 000, 50 powtórzeń — 7 wariantów tablic.
rodzaj tablicy avg (ms) min max względnie

Uwaga metodologiczna: DICTIONARY ma length ≈ 20×N, więc pętla iteruje ~20× więcej slotów — część „wolności" to iteracja po dziurach, nie sam tryb słownikowy. Samo a[i*10]=i bez skoku nie uruchamia dictionary mode (każdy zapis <1024 ponad length).
