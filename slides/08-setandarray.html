Set vs Array

arr.includes(x) skanuje liniowo — O(n). set.has(x) liczy hash i patrzy w jeden bucket — O(1). Przy częstym sprawdzaniu przynależności lub deduplikacji Set wygrywa o rzędy wielkości.
ARRAY
Ciągły blok pamięci — świetny przy iteracji sekwencyjnej (prefetch CPU), kompaktowy
includes / indexOf — O(n); deduplikacja przez filter + indexOf to O(n²)
Dla małych kolekcji (< ~100 elementów) bywa szybszy i lżejszy niż Set
SET
Hash mapa (OrderedHashSet) — has/add/delete O(1), zachowuje kolejność wstawiania
Unikalność z definicji — new Set(arr) deduplikuje w jednym przebiegu
Narzut pamięciowy hash tabeli — płacisz pamięcią za czas
benchmark 1 — sprawdzanie przynależności
✗ Array.includes — O(n)
// zbiór 100 000, 1 000 losowych zapytań
function searchArray(arr, queries) {
  return queries.filter(q => arr.includes(q));
}
✓ Set.has — O(1)
// te same dane i zapytania
function searchSet(set, queries) {
  return queries.filter(q => set.has(q));
}
100 000 elementów, 1 000 zapytań, 200 powtórzeń.

benchmark 2 — deduplikacja
✗ filter + indexOf — O(n²)
function dedupArray(arr) {
  return arr.filter((v, i) => arr.indexOf(v) === i);
}
✓ [...new Set(arr)] — O(n)
function dedupSet(arr) {
  return [...new Set(arr)];
}
