WeakMap / WeakRef

Klucz w Map trzyma obiekt przy życiu — cache na Mapie to gotowy wyciek. WeakMap trzyma klucz słabo: gdy reszta kodu zapomni o obiekcie, GC zbiera go razem z wpisem.
WeakMap / WeakSet
Klucze tylko obiekty; brak iteracji i .size — rozmiar z definicji nieznany (GC decyduje)
Użycie: metadane obiektów spoza Twojej kontroli, cache, „czy już przetworzony?"
WeakRef + FinalizationRegistry
.deref() → obiekt albo undefined, jeśli już zebrany
Spec celowo nie gwarantuje kiedy (ani czy) callback finalizacji się wykona
unikaj gdy…
…potrzebujesz iteracji, rozmiaru lub deterministycznego cyklu życia — wtedy zwykły Map/Set + jawne sprzątanie
demo — Map więzi obiekty, WeakMap nie
✗ Map — silna referencja do klucza
const cache = new Map();
function process(req) {
  cache.set(req, compute(req));
  // req żyje dopóki żyje cache → wyciek
}
✓ WeakMap — GC może zebrać klucz
const cache = new WeakMap();
function process(req) {
  cache.set(req, compute(req));
  // caller porzuca req → GC zbiera req + wpis
}
10 000 obiektów, FinalizationRegistry liczy, ile GC faktycznie zebrał.
