Optymalizacja JS — silnik V8

Argumenty funkcji i deoptymalizacja

MONOMORPHIC — ideał
Definicja — funkcja zawsze wywoływana z argumentami tego samego typu i kształtu (hidden class)
Co robi V8 — Turbofan kompiluje wyspecjalizowany kod maszynowy zakładając konkretny typ; dostęp do pól to stały offset
Inline cache — IC zapamiętuje jeden kształt; trafienie = brak lookupów
Przykład — add(1, 2) zawsze z liczbami całkowitymi → V8 generuje instrukcję ADD bez sprawdzania typów
POLYMORPHIC — wolniej
Definicja — funkcja widziana z 2–4 różnymi kształtami argumentów
Co robi V8 — IC trzyma małą tablicę kształtów i sprawdza każdy po kolei (linear search); nadal może być JIT-owany
Koszt — kilka porównań kształtu przy każdym wywołaniu zamiast jednego trafienia
Przykład — process(obj) gdzie obj ma raz {x,y}, raz {x,y,z}
MEGAMORPHIC — bailout
Definicja — ponad 4 różne kształty; IC się poddaje i przełącza w tryb globalny
Co robi V8 — każde wywołanie odpytuje globalny stub cache (hash lookup); brak specjalizacji, brak inline cache
Deoptymalizacja — Turbofan może wycofać skompilowany kod i wrócić do interpretera (bailout), jeśli założenie o typie zostało złamane
Przykład — generyczna funkcja serialize(x) wywoływana z dowolnym obiektem
✓  Monomorphic — jeden kształt argumentu
// Zawsze ten sam kształt {x, y} → V8 specjalizuje
function distanceMono(p) {
  return Math.sqrt(p.x * p.x + p.y * p.y);
}

const points = Array.from({ length: N },
  (_, i) => ({ x: i, y: i }) // jeden hidden class
);
points.forEach(p => distanceMono(p));
✗  Megamorphic — wiele różnych kształtów
// Każdy obiekt ma inny kształt → IC się poddaje
function distanceMega(p) {
  return Math.sqrt(p.x * p.x + p.y * p.y);
}

const shapes = [
  { x: 1, y: 1 },           // kształt A
  { y: 2, x: 2 },           // kształt B (inna kolejność!)
  { x: 3, y: 3, z: 0 },     // kształt C
  { x: 4, y: 4, label: '' },// kształt D
  { r: 5, x: 5, y: 5 },     // kształt E → megamorphic
];
// cykl przez 5 kształtów → brak specjalizacji

REGUŁA KCIUKA
Trzymaj jeden kształt
Twórz obiekty zawsze w tej samej kolejności pól. {x,y} i {y,x} to dwa różne hidden classes dla V8.
Nie mieszaj typów
Funkcja wywoływana raz z liczbą, raz z null, raz z obiektem straci specjalizację. Dodaj guard na wejściu lub rozdziel na osobne funkcje.
Unikaj delete
delete obj.prop zmienia hidden class obiektu → wszystkie funkcje używające tego kształtu muszą się zdeoptymalizować.
