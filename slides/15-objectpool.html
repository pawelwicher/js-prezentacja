Object Pooling — reużywanie obiektów

BEZ POOLINGU — ciągła alokacja i GC
Każda operacja — tworzy nowy obiekt na stercie; po użyciu staje się śmieciem
Minor GC (Scavenge) — V8 uruchamia minor GC gdy young generation się zapełni (~1–8 MB); wstrzymuje wykonanie na 1–5 ms
Major GC (Mark-Compact) — po wielu minor GC; pauza 10–100 ms widoczna jako jank w animacjach (poniżej 60 fps)
Presja alokacji — im szybciej tworzysz obiekty, tym częstsze GC; w grach lub animacjach (60 fps = 16 ms/klatka) jedna pauza GC = utracona klatka
Z POOLINGIEM — zero alokacji w hot path
Idea — z góry alokujesz pulę obiektów; zamiast new bierzesz obiekt z puli, resetujesz pola, używasz; po użyciu oddajesz do puli
Zero alokacji w hot path — GC nie ma co zbierać; pauzy znikają lub drastycznie maleją
Hidden class stabilna — wszystkie obiekty z puli mają ten sam kształt (tworzone w tym samym miejscu); IC zawsze monomorphic
Kiedy warto — obiekty krótkotrwałe tworzone w pętlach (cząsteczki, eventy, wektory 2D/3D, żądania w kolejce)
✗  Bez poolingu — new przy każdej cząsteczce
function updateParticles(count) {
  const particles = [];
  for (let i = 0; i < count; i++) {
    // nowy obiekt na stercie przy każdym wywołaniu
    particles.push({
      x: Math.random() * 800,
      y: Math.random() * 600,
      vx: (Math.random() - 0.5) * 4,
      vy: (Math.random() - 0.5) * 4,
    });
  }
  // po zakończeniu klatki wszystkie obiekty
  // stają się śmieciami → GC musi je zebrać
  return particles;
}
✓  Object pool — reużywanie, zero new w pętli
class ParticlePool {
  constructor(size) {
    // alokacja jednorazowo przy starcie
    this._pool = Array.from({ length: size },
      () => ({ x: 0, y: 0, vx: 0, vy: 0 }));
    this._free = this._pool.length - 1;
  }
  acquire() {
    return this._free >= 0
      ? this._pool[this._free--] : { x:0,y:0,vx:0,vy:0 };
  }
  release(p) {
    if (this._free < this._pool.length - 1)
      this._pool[++this._free] = p;
  }
}
const pool = new ParticlePool(10_000);
// acquire() / release() — zero alokacji
